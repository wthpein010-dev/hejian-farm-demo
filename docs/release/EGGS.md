# 每日鸡蛋登记与手动收取

2026-10-27。依据原始养鸡、每天手动收蛋及持续迭代需求。只对 development 服务中的 development 身份开放；全部验证使用合成动物、人员和临时数据库。生产、真实人员身份、农场数量、保鲜和实体履约仍待验收。

## 对象与产出

既有 animal 归属档案还须由私有配置明确为 `chicken-eggs`，绑定账户、环境与种养轮次，并单独指定记录人员和当天数量上限。不能从动物名称、数量或播种人员权限推断这是鸡或应该产几枚蛋。启用只接受正在饲养或可收获的本轮档案；关闭仍可撤销人员权限。

记录人员填写当天实际数量与规范来源编号，服务器决定上海产出日。每轮每日最多一笔有效批次，同一来源编号不可重复。数量上限是可修改的开发样本，不能作为农场真实产量承诺。输入框保留字段名称、灰色示例提示及纠错说明；提示不是预填数据。

批次从“待收取”只能变成“已收取”或“已撤回”。未收批次可由当前授权人员撤回，再以新来源编号更正登记；已收批次不能通过撤回扣减账户。历史未收记录继续可核对，不按计时自动生产或销毁，也不冒充已质检、可寄出库存。

## 用户手动收取

用户只能收取本人本轮、当前许可的待收批次，不能填写或修改数量。收取同时核对批次版本与财务 revision；同一事务将批次标记为已收、收入鸡蛋并保存原结果。重复原操作回放原结果，新操作再次领取会明确拒绝。

收取继承现有 harvest 事件：累计鸡蛋增加登记数量，成长经验增加 8，今日与累计收获次数各增加一次，并影响原有任务及成就资格。工作人员登记、撤回不增加客户资产、经验或奖励。溢出、版本冲突或事务失败不产生部分发放。

仓库继续表达“累计收获”，不是当前可配送余额。配送、冷链、损耗、地址及运费没有在本切片中自动接通。

## 服务边界

`shared/eggs.mjs` 拥有严格命令、配置和读取 DTO；`services/api/src/eggs.mjs` 拥有配置、独立人员授权、批次与最小命令账四表。schema10 接入；账户资产及外层 IMMEDIATE 事务仍由 FarmStore 拥有。

读取接口相对 `/api/v1`：

| 路由 | 用途 |
|---|---|
| `GET /eggs/status` | 服务状态与本人记录权限入口 |
| `GET /eggs/record/{recordId}` | 本人动物档案的配置及当天批次 |
| `GET /eggs/batches/{cursor}` | 本人的产出批次，每页20笔 |
| `GET /eggs/batch/{id}` | 本人指定批次及当前可收权限 |
| `GET /staff/eggs/records/{cursor}` | 当前授权的登记对象，每页20项 |
| `GET /staff/eggs/record/{recordId}` | 当前授权对象的登记资格 |
| `GET /staff/eggs/batches/{cursor}` | 当前授权对象的批次 |
| `GET /staff/eggs/batch/{id}` | 当前授权批次及撤回权限 |

新命令只经[唯一恢复协议](RECOVERY.md)准备与执行，必填 `domain:'eggs'`。记录人员使用 `register` 或 `withdraw`，客户使用 `collect`；精确字段和枚举以 shared 模块为准。命令不接受用户提供的身份、日期、奖励、动物数量推算或任意备注。

原最小回执保留操作、结果、批次编号和确认时间；只有收取成功才有发放 quantity 与 appliedRevision。原回执先于当前权限检查，撤权后仍可确认原操作，但不获得当前动物资料的读取或写入权限。旧回执不能复活撤回批次。

## 冷启动与资产

播种和鸡蛋操作共用一个服务端槽、一个客户端 pending 和同一原结果面板。旧播种命令没有新增 domain 字段，原 JSON 字节、指纹、编号和 prepare 墓碑不重写；新鸡蛋动作通过严格固定域分派执行与账目验证。

冷启动准备态由用户明确继续或放弃，普通检查不自动执行。原结果与当前列表、当前资产分别读取；读取失败不重收。客户端看到收取成功回执后建立本账户、环境的最低已确认资产版本。确认原结果可独立完成；在最新快照达到该版本前，新业务提交保持锁定并提供刷新入口，不能把旧资产当成最新状态。

## 私有配置、注销与备份

`tools/provision-eggs.mjs` 只操作明确的既有私有 schema10 数据库与私有 JSON 文件，先完整只读检查，再按配置版本提交；不会创建真实人员、从文件名猜身份或自动迁移用户运行库。

账户注销先处理仍开放的恢复项，再清理本人的产出配置、批次及真实人员关联；仅有未收批次不造成无法解除的注销锁。其他账户保留的最小历史确认不会恢复已删除对象；其命令账另保留原目标账户和档案的随机引用，以区别合法删除与批次丢失，不把引用下发为当前鸡舍资料。真实保留制度仍待核定。相关配置与业务变化撤销未使用的注销准备。

备份共用固定 DDL、索引和内容验证；旧 schema2–9 保留旧协议边界，旧 schema9 不允许伪造鸡蛋意图。恢复禁用鸡蛋配置、撤销人员授权并递增版本，继续轮换恢复 epoch、隔离 prepared，保留原 settled 回执字节。禁权不等于完成快照外资产、撤权和删除记录的灾备核对。

历史账、批次和恢复墓碑仍随操作增长，生产容量、保留和备份删除清单未核定。公开 Pages 继续运行内存 H5，发布源码与跨端资源不代表本服务已部署、官方小程序已审核或真实鸡蛋已发货。

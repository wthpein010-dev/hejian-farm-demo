# 账户数据与注销工程验收

2026-10-27。本页记录可运行的账户管理功能，不是隐私政策、法律合规或平台审核证明。当前服务没有接入真实认养、现金支付、收货地址或实体订单。

## 用户流程

跨端“我的”页可查看当前账户保存的数据类别。注销需要先刷新并核对账户、积分物资和兑换记录，再进入独立确认区。默认焦点落在“返回，保留我的账户”，最终动作为“确认注销当前账户”。准备或取消不会删除账户。

只有收到服务端有效完成回执后才显示已注销，并清除客户端账户、资产和隐私快照。结果未知时锁定重新登录、退出和资产操作，保留原确认凭证，提供“核对上次操作”；会话已经失效也可以核对。限流、来源拒绝、通用登录错误等未到达注销处理的回复不能让客户端丢弃凭证。

## 服务契约

| 请求 | 校验与结果 |
|---|---|
| `GET /account/privacy` | Bearer所属账户的数据类别、资料和更新时间；不接受userId，不返回平台身份摘要、会话摘要或凭证 |
| `POST /account/deletion/prepare` | 仅接收expectedRevision；5分钟内新会话、有效授权与当前版本。准备返回2分钟高熵确认凭证，仅摘要入库 |
| `POST /account/deletion/confirm` | 仅POST正文中的confirmationToken；有效准备再次校验原会话、期限和版本，SQL事务删除账户及其会话、资产和操作记录 |

路径统一以 `/api/v1` 为前缀。确认接口可不带Bearer，因为全部会话已经删除后仍需核对丢失的回复；秘密能力凭证必须保存在运行内存中，禁止URL、storage、日志或分析事件。返回的完成回执只有deleted及completedAt。

成功后仅保存不关联用户的随机凭证摘要和完成时间；同凭证重复核对返回原结果，不删除后来同身份新注册的账户。未知/撤销确认为410 DELETION_INVALID，过期为410 DELETION_EXPIRED，原登录无效为401 REAUTH_REQUIRED，账户变化为409 DELETION_STATE_CHANGED；这四组协议明确拒绝可结束当前尝试。其他未证实结果继续保留核对能力。

schema2→3只增加准备与匿名回执两表，保留已有账户资产；高于当前版本的数据库拒绝降级启动。

## 证据与范围

- 后端13项真实HTTP/SQLite回归：授权和跨用户、5分钟/2分钟边界、慢正文期间会话/版本重验、并发与故障回滚、全部会话失效、重启/重放、重注册隔离及迁移。
- 客户端与真实HTTP联调：取消、错误资料、迟到跨账户回包、有效回执、丢响应、会话过期、错误身份、通用4xx核对及真实限流后的同凭证恢复。
- 浏览器已操作数据类别查阅、注销准备和取消；默认焦点为返回按钮，取消回原入口。320px iframe实际检查文本换行、底部安全区与确认按钮可达；近期登录过期时出现重新登录入口。浏览器没有对真实用户账户执行注销；成功删除由专用临时测试账户的HTTP/SQLite闭环验证。
- 新增功能需重新类型检查和四端编译，结果统一记录在PROGRESS；不能用旧构建产物证明本轮代码。

## 正式上线仍需补齐

运营主体、可联系渠道、正式隐私告知和授权、真实地址与订单的数据范围、法定保留及争议/履约处理策略仍未核定。接入真实支付、认养或实体订单后，注销协议必须按核定保留规则扩展，不能直接复用当前无真实经营数据的即时删除语义。

在线业务记录删除不等于历史备份或介质即时擦除。[备份恢复说明](../../services/api/BACKUP.md)要求恢复后旧会话和未使用注销确认失效，并隔离核对最新注销清单。历史备份、灾备切流、保留期限及删除执行仍需生产验证；此门槛未完成前不视为正式上线通过。

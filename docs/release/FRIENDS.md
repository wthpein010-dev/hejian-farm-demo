# 持久农友关系

日期：2026-10-27。当前为正式工程的开发沙盒切片，生产能力关闭；实现与测试结果以本轮验收记录为准。公开 `prototype/` 的好友仍为内存示例，这里的账户关系不与其名单混用。

## 开通和关系

登录用户主动开通后，服务器生成独立32位十六进制公开农友ID和128bit随机农友码，系统别名由公开ID派生。不采集通讯录，不允许自填公开昵称，不提供用户目录、模糊搜索或用户预览。已知农友码通过POST正文申请；代码、会话和私人列表不进入URL、storage或日志。本人可以主动复制自己的码交给朋友；复制不代表有效拉新或自动成为好友。

申请方可以撤回，接收方可以接受或拒绝。双方同时申请仍需明确接受。成为好友不授予对方查看资产、兑换、私人农场档案、设备或镜头的权限。移除使关系立即失效；屏蔽同时移除双方申请/好友，解除只清除屏蔽，不恢复关系。关闭名片撤销旧码、清空自己的关系/主动屏蔽；他人对自己的屏蔽继续有效。停用行保留公开ID、版本、额度及时间，用于防止版本重置、重复刷申请和绕过他人屏蔽；原最小命令账也保留。重新开通会生成新码，账户注销才原子删除上述记录。

当前提案上限为每账户200条活动关系（含申请）、200个主动屏蔽，以及按服务器北京时间每日20次新申请。历史限额不因关闭/重开重置。没有社交积分、邀请奖励、消息通知、好友农事或内容发布；论坛审核与举报处置另行建设。

## 独立协议

所有接口要求现有Bearer会话，账户与环境由服务端解析，客户端不能指定ownerId。统一私有no-store响应与固定路由日志。

- `GET /api/v1/friends`：完整有界列表，字段 `friendsFormat:1,ownerId,environment,serverTime,version,available,enabled,profile,friends,incoming,outgoing,blocked`。`profile`是`null`或`{code,alias}`，各列表项为`{peerId,alias,createdAt}`。`version`是独立社交版本，涉及双方的关系变化会更新双方版本，与资产revision分开。
- `POST /api/v1/friends/commands`：必需`Idempotency-Key`；正文`{action,expectedVersion}`，申请另带`code`，关系操作另带`peerId`。动作：`enable/disable/request/accept/decline/cancel/remove/block/unblock`。未知字段或非法形状400，未鉴权401；读取完整正文后再次核验会话。先找原回执，再校验本人社交版本；不匹配以`FRIENDS_CHANGED`确认拒绝，需要刷新后重新确认，不自动重发。停用/重开不重置版本，注销递增受影响存活农友的版本，防止旧操作误作用于后来重建的关系。
- 合法命令响应HTTP200：`{data:{friendsFormat:1,ownerId,environment,operationKey,action,outcome,code,completedAt},requestId}`。`outcome`为`applied`或`refused`。合法拒绝也是可确认的最终结果，不以HTTP成功状态冒充关系已建立。

命令结果使用独立账而非金融幂等表。只保存最小结果和请求指纹，不保存农友码、peerId、他人资料或列表快照。相同账户/key/正文重放原结果；同key异正文明确拒绝，不替换原记录。第一次申请成功后即使后来被取消、拒绝、移除或屏蔽，旧key重放也不会重新建关系。成功/拒绝确认后另读当前列表，避免把过去回执当成现在的关系。

拒绝码为`FRIENDS_UNAVAILABLE/FRIENDS_DISABLED/FRIENDS_CHANGED/PEER_UNAVAILABLE/ALREADY_PENDING/ALREADY_FRIENDS/REQUEST_NOT_FOUND/RELATION_NOT_FOUND/BLOCK_NOT_FOUND/FRIEND_LIMIT/BLOCK_LIMIT/DAILY_REQUEST_LIMIT/IDEMPOTENCY_CONFLICT`，应用成功为`OK`。自己、缺失、未开通、被任一方向屏蔽及不同环境均以统一不可添加结果处理，不暴露屏蔽原因或账户存在性。

## 客户端恢复

社交复用唯一会话和待核对操作槽；不把社交回复交给资产Snapshot解析。未确认命令保留原key/body，防止换key重建关系。已未知操作后的通用4xx、限流和5xx不能丢请求；401清私有资料并仅允许原账户重新登录核对。命令的合法同账户/同环境/同key/同action回执才能结束核对，之后单独刷新列表。刷新失败只重读，不再发新命令。

账户/会话变更、注销、退出使旧读取失效；写入开始会作废之前的关系读取。最新有效视图需要通过字段、归属、版本与列表校验。数据及待核对状态仅运行内存，重启客户端不会自动恢复未确认命令；这仍是生产恢复设计需要覆盖的边界。

## 存储、注销与恢复

schema6由服务端朋友模块单源维护DDL及数据校验，备份工具共用固定表、索引和外键合同。schema2–5仍可校验并由当前服务升级；旧schema5服务应拒绝schema6且不修改库。测试只能对自己创建的临时合成数据库升级，不对用户运行数据迁移。

注销事务删除本人名片、双方关系、涉及本人的双方屏蔽、命令账和限额；原农场档案、资产、会话和匿名注销回执遵守既有契约。社交操作不改变金融Snapshot、revision、奖励或原兑换回执。

备份恢复继续清旧会话及未用注销确认。结构、归属与SHA256校验不能证明备份真实性或最新性；旧备份可能复活后来已移除的关系、撤回的同意或已注销账户。正式切流仍需最新撤销/删除记录、保留政策、访问控制、加密及隔离演练。

生产开放还需真实平台身份/服务部署、隐私及运营主体告知、反滥用策略与处置、真机/官方平台验证。开发沙盒可持久化不等于这些门槛已经通过。

列表和每日申请上限不限制命令历史总容量；不同key的成功与合法拒绝仍持续累积。生产前需要容量/保留及撤销设计，不能静默删除旧key从而破坏原结果重放。

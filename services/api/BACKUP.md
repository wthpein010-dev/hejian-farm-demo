# SQLite 备份与隔离恢复

日期：2026-10-27。工具要求 Node.js 24.15.0 或更新版本，不安装额外依赖。当前支持本应用数据库 schema **2、3、4、5、6、7、8、9**；未知未来版本、缺表、异常主键/外键结构、非本应用数据库及无法被现行领域规则接受的资产状态会拒绝。工具不会自动降级 schema。schema8播种和schema9[操作恢复](../../docs/release/RECOVERY.md)分别共用模块固定DDL/索引与内容验证。

这是可运行的本机备份/恢复工具及临时数据测试证据。生产备份存储、加密、权限、保留期限、恢复时限、异地副本和恢复演练尚未验收，不能据此开放正式生产恢复。

## 在线备份

先由运维创建并保护彼此分离的数据库目录、备份父目录及隔离恢复父目录。工具只接受显式绝对路径；父目录必须已经存在，`--output` 指定的整个目录必须不存在。以下路径均为占位示例，不是当前机器已配置的生产位置：

```powershell
node services/api/tools/backup.mjs `
  --database 'D:\PrivateFarm\data\farm.sqlite' `
  --output 'D:\PrivateFarm\backups\2026-10-27T120000Z'

node services/api/tools/verify.mjs `
  --backup 'D:\PrivateFarm\backups\2026-10-27T120000Z'
```

备份使用 Node 内置 `node:sqlite.backup()` 的 SQLite 在线备份协议，可从仍在写入的 WAL 数据库生成一致副本。不要运行普通文件复制来单独复制正在运行的主库。备份包含备份快照时已确认的账户、资产、幂等回执、登录凭证摘要和服务端时间；正在并发进行或之后才确认的事务不保证包含。繁忙写入会增加备份耗时和 I/O，生产容量与时间预算须另行测量。

成功目录只有两个文件：

- `farm.sqlite`：已转换为 DELETE journal 模式的独立数据库，无需原库的 WAL/SHM。
- `manifest.json`：格式版本、UTC创建时间、schema版本、数据库字节数与SHA-256；没有账户列表、token或业务内容。

工具对源库与目标库执行 `PRAGMA integrity_check`、`PRAGMA foreign_key_check`、应用表/列/主键/外键及领域状态检查，并检查备份哈希。schema2/3/4同时匹配固定DDL约束与已知索引白名单，包括身份唯一性、CHECK/NOT NULL/默认值及索引的唯一性、来源、列和排序规则；手动添加或改变索引也会拒绝。SQL仅规范化空白、关键字/标识符大小写和标识符引用，不改写字符串字面量。后续schema/索引变更须同步版本契约与恢复验收，不能为了恢复而移除校验。

schema4支持[版本化无损回执](RECEIPTS.md)，同一库可含原始JSON和压缩envelope；schema2/3中压缩envelope会拒绝。服务与备份共享严格解码器，先验证预算、完整输入、UTF-8、长度和校验和，再执行下方业务归属检查。压缩不是加密，也不代表历史容量已受控。

成功幂等回执须属于该行用户的profile与环境，revision及服务器时间必须完整、合法且在当前账户版本/服务时间内，目录、任务、签到、等级和能力开关等元数据须与该历史状态及现行领域规则一致。另一账户的合法Snapshot不能借清单重算哈希后通过恢复。清单写入会循环补齐合法短写，零进度写入失败；返回成功前重新校验生成的完整清单和数据库。

成功CLI输出一行JSON：`ok`、`operation`、格式/schema版本、字节数、SHA-256。失败退出码为1，仅输出固定错误分类及脱敏原因，不输出SQL、堆栈、数据库路径或记录内容。

清单中的SHA-256用于发现损坏或文件不匹配，**没有签名或MAC**。可同时修改数据库和清单的人仍可能制作通过结构检查的备份；真实备份必须依赖存储访问控制、不可变副本及独立可信的校验记录。

## 只恢复到新目录

```powershell
node services/api/tools/restore.mjs `
  --backup 'D:\PrivateFarm\backups\2026-10-27T120000Z' `
  --output 'D:\PrivateFarm\recovery\isolated-2026-10-27'
```

恢复先完整校验备份，再新建私有目标目录和 `farm.sqlite`；任何既有目录/文件都不覆盖，不向正在运行的数据库恢复。恢复目录与备份目录必须互不嵌套。备份目标也不得位于源库所在目录内或成为源库目录的上级。

恢复完成后**默认删除恢复库全部 `sessions` 和 schema>=3 的 `deletion_confirmations`**，不提供保留历史会话的开关。schema8另外禁用全部播种计划、撤销全部人员授权并递增版本；已撤销授权也递增，必须可信重新核查/配置后再开放作业，避免旧备份复活后来撤销的权限。备份可能早于退出、过期撤销或销毁确认；这些旧Bearer token和未完成的注销确认不能重新获得效力。账户、资产、原幂等回执、平台code使用摘要和匿名 `deletion_receipts` 保留。用户重新登录相同账户后，持有原正文、原版本和原幂等键的已完成请求仍恢复原结果，不会再次扣分或发放；仅内存凭证丢失不能据此自动恢复。真实平台重新登录仍必须使用新的官方code。

恢复报告的 `sourceSha256` 是原备份的哈希；`sha256` 和 `bytes` 是清除历史会话后恢复库的实际值，另有 `sessionsInvalidated: true`。恢复不会修改原备份，也不会把恢复库当作新的备份清单发布；如需备份它，应重新执行在线备份命令。

schema9还会轮换操作恢复epoch、每个账户槽版本递增，并将open prepared意图隔离为quarantined；settled原回执保持原值。隔离意图不能自动执行、用户ack或放弃，不因重新授权而复活。必须按下述隔离灾备流程核查快照外操作；工具没有伪造“未执行/成功”回执来解除阻挡。当前未提供用户自助解除。

恢复库保持隔离，暂不连接公开入口或真实设备。生产切换前至少要完成：

1. 与受保护、最新的注销/删除及撤销记录核对。旧备份可能包含后来已注销的账户，清空会话**不能**阻止这些账户通过重新登录复活；该工具尚未自动接入最新删除清单。
2. 明确恢复点后的数据损失范围并核对资产、回执、订单和其他外部系统。当前时间快照也可能早于后来观察到的时间；不能将回滚恢复当成跨灾难环境的完整防重证明。
3. 在隔离环境用当前服务版本启动，验证身份、授权、资产及原key重试，核查记录仅保留必要脱敏结论。schema2–8由服务正常迁移至当前schema9；工具本身不迁移。旧schema8服务拒绝打开schema9，不能降级绕过新权限/状态契约。
4. 按真实部署的停流/维护与回滚流程切换数据库配置，完成监控和业务核对后再恢复访问。该工具不重启服务、不改配置、不自动切流。

## 权限、秘密与保留

POSIX创建目录模式为0700、文件为0600，且拒绝路径中已有的符号链接、Windows junction、非常规文件和硬链接输入；操作前后核对路径链与文件身份。目标文件以exclusive create保留，重复运行须选择全新目录。失败清理只删除仍属于该操作的文件，不递归追随被替换的路径；无法安全清理时可能留下不完整的私有目录，应由运维核对后处理，不把缺清单的目录当成成功备份。

Windows的Node文件模式不能替代NTFS ACL，目录flush也未取得真实断电证据。部署前由管理员设置仅备份/服务身份可读写的ACL，并验证继承、磁盘及共享权限。现有父目录须受保护，备份和恢复操作期间不得由其他进程移动、替换或修改路径。路径检查和Windows SQLite活跃文件锁已做本机测试；不承诺抵抗可绕过权限的同身份进程或管理员持续竞态攻击。

SQLite及备份目前未提供内置加密。备份包含账户资料、资产、身份/会话摘要和历史回执，按敏感数据保存；不要提交Git、发到公开Pages或普通下载链接。生产需由运维为磁盘及异地备份配置受管加密、密钥托管、最小授权、审计与轮换，恢复演练应验证密钥可用。密钥与备份分离，不将密钥写入命令、仓库、清单、日志或聊天。

备份频率、RPO/RTO、保留期限、异地/不可变副本、过期删除、失败告警和定期演练责任人尚待确认。账户注销需覆盖历史备份保留与恢复后的删除重放流程；不能只删除在线库后永久保留可复活的旧副本。匿名注销回执不包含用户映射，不能独立作为所有历史备份的完整删除清单。任何依法需保留的最小记录及到期销毁口径须另行核定。

## 已实际运行的验证

```powershell
node --test services/api/test/backup.test.mjs
node --check services/api/tools/sqlite-backup.mjs
node --check services/api/tools/backup.mjs
node --check services/api/tools/verify.mjs
node --check services/api/tools/restore.mjs
```

原备份基线23项测试仅在随机临时目录创建虚构账户/数据库，全部HTTP服务使用现有Fetch安全端口helper。实际覆盖：活跃WAL与并发HTTP写入时备份；已确认50积分/9份饲料及丢响应回执恢复；原库整个目录移除后独立恢复；旧会话401、重登同账户及原key重放不重复扣款；schema2/3、注销确认清理与匿名回执保留；哈希/SQLite损坏/外键/缺表/坏领域状态/未来schema拒绝；既有目标与原文件保护；目录嵌套、链接与输出替换；CLI运行和脱敏；缺失身份UNIQUE、额外UNIQUE索引、缺失code CHECK/非法状态；他人回执及环境/版本/时间/派生元数据错误；清单短写和零写。短写测试只替换当前测试进程的Node文件写边界，仍读写真实临时文件，并检查最终文件可独立校验。

已先运行真实HTTP兑换后的缺工具RED，再实现GREEN。会话清理新增断言先实际收到200（应为401）及清理后数量仍为1（应为0），修复后通过；负数库存状态也先被错误接受，补上共享领域规则验证后通过。Windows实际阻止活跃SQLite目标文件重命名（EBUSY）；允许替换的平台则检查身份变更后拒绝发布清单，并保留不属于操作的替换文件。上述是本机测试证据，尚不等于真实生产备份、权限、保留与灾备演练。

独立审查又复现约束/索引漏检、成功回执归属漏检及清单单次短写错误报告成功。补充14项先全部RED：12项错误数据被接受、短写成功后校验为INVALID_MANIFEST、零写仍报告成功。修复后专项23项全部通过，仍不把结构与SHA-256检查当成备份真实性签名或完整生产恢复证明。

## schema5档案校验

新增档案/逐版本观测/匿名批次表按registry单源DDL检查，包括复合外键、索引、连续版本、归属/时间/生命周期和最后事件一致性。重算文件hash不能绕过应用结构与数据校验；恢复仍清会话和未用注销确认。导入与生产边界见[农场档案](../../docs/release/FARM-RECORDS.md)。

## schema7论坛校验

帖子/评论、日额度、举报、最小用户命令及审核批次五表使用forum单源DDL/索引。校验父子kind/圈子/状态/时间、撤回后文本清空、非沙盒关闭、额度、回执归属和无正文审核元数据/指纹；旧schema2–6不被误要求带新表。`inspectApplicationDatabase`仅用只读连接检查同一完整合同，供私有审核CLI在打开写连接前复用，不导出UGC。

恢复继续清会话/未用注销确认；已撤回/隐藏内容和注销账户仍可能因旧备份复活，正式切流必须使用最新撤销/删除记录。CLI导出的私有审核文件亦含待审正文，须单独按权限/保留要求处理，不能公开下载。当前本机开发验证不等于真实审核、加密/保留、人员权限或灾备验收，详见[FORUM](../../docs/release/FORUM.md)。

## schema6农友校验

新增名片/关系/屏蔽/最小命令账四表由friends模块单源DDL检查，包含固定主键/唯一索引/外键、同环境与启用状态、关系与屏蔽互斥、人数/额度、独立社交版本/时间和回执归属。社交不写金融回执或改变资产revision；历史原命令回执恢复后仍阻止旧申请复活关系。完整协议见[FRIENDS](../../docs/release/FRIENDS.md)。

隔离恢复保留备份时的名片、关系、额度与最小命令账，继续清会话及未用注销确认；旧备份仍可能复活后来撤回的名片同意、已移除关系或账户。正式切流必须与最新撤销/删除记录核对，不能把结构校验、清会话或本机恢复当作已完成这一生产要求。列表/每日额度不限制命令账总容量，保留/容量仍待核定。

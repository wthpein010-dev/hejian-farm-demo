# 历史回执存储与核对

日期：2026-10-27。API线协议仍为v1；金融回执编码由schema4引入；当前schema5新增独立农场档案表，不改回执格式。成功操作先按账户、key和请求指纹查询原回执，命中时返回当时的完整Snapshot，不能改返最新资产或重新执行。未确认操作的客户端核对规则见[API契约](../../docs/release/API-CONTRACT.md)。

## 无损编码

`src/receipt-codec.mjs`是服务与备份工具共用的唯一编解码实现。`idempotency.success_json`仍是TEXT：保留原始JSON，或保存四字段envelope：`receiptEncoding: deflate-raw-v1`、`utf8Bytes`、`sha256`和`payload`。payload为标准Base64的deflate-raw内容，SHA256针对原始UTF-8 JSON。

新写入只在原始结果为1024字节至8MiB、且完整envelope实际更小时压缩，使用level1。较小、压缩无收益或超过8MiB的结果保持原始JSON；不裁剪回执，也不增加新的经营额度。8MiB是压缩工作／解压窗口预算，**不是全局响应或历史容量上限**。压缩不是加密，数据库及备份仍需受保护。

解码严格检查字段、格式版本、canonical Base64、压缩输入与声明输出预算、完整输入消耗、实际字节数、SHA256、UTF-8及对象结构。损坏、截断、尾随数据、未知格式或解压炸弹均失败关闭，错误不回显内容。服务回放还检查回执账户和环境；备份另核对版本、时间、领域状态及派生元数据。不能仅凭压缩内容能解开就认定业务回执有效。

## 升级、备份与回退

当前服务启动将旧库升级到schema5，不批量重写旧回执；已保存的原始JSON保持原字节，新回执可使用压缩。schema2/3/4/5备份都使用固定SQL结构、约束及索引检查，schema2/3中出现压缩envelope会被拒绝。schema4允许旧原始与新压缩格式混合。新格式只影响内部存储，HTTP重放仍是原Snapshot。

恢复仍仅写全新隔离目录，删除旧sessions和schema≥3的未用注销确认。账户资产、原回执及匿名注销回执保留。重新登录后使用原key、原版本和正文核对，不换key重复兑换。编码或持久化失败时，状态、券、库存和新key一起回滚。

schema3旧服务拒绝打开schema4，不允许通过手工改低`user_version`回退。上线前先备份旧库，在隔离路径使用新服务演练，验证原key重放和业务资产，再按正式停流流程切换。本轮只操作自有临时数据库，没有迁移或压缩用户运行库；跨发布版本的规则变化、生产删除清单与灾备切流仍需单独验收。

## 已测收益和未完成边界

相同4000次交替加减购物车的合成工作集，当前账户状态仍为566字符，回执仍为4000条。新文件库回执TEXT实际9,786,724 UTF-8字节，完整解码后的原JSON为17,202,893字节，减少43.11%；SQLite已分配页由旧诊断18,759,680字节变为16,748,544字节，减少约10.72%。记录文本的比例不能冒充整个数据库、WAL或生产磁盘同等下降。

本机当前120秒、4worker真实HTTP负载11512请求全响应，0错误/5xx，4账户重启及原结果核对、清理通过；p95为16.012ms，RSS60.28→180.54MB。请求节奏、主机、SQLite分配、压缩与历史增长都会影响结果，不据此声称生产容量、无泄漏或长期稳定。

本轮没有规定或执行回执删除。成功回执、失败key、平台code摘要和匿名注销回执仍随使用增长；生产还需要用户规模、容量准入、保留／删除和期满后的核对语义。不能为省空间静默删除旧key，否则旧兑换可能被视为新请求。压缩降低存储比例，不能把无限历史变为有界。

可复核证据：`test/receipt-codec.test.mjs`、`test/receipt-storage.test.mjs`及原备份/账户/幂等测试；本机脱敏数值和降级演练位于`.scratch/receipt-storage/`，不含真实用户或生产数据库。

当前schema5的农场归属档案与观测独立于金融Snapshot，详见[档案接入](../../docs/release/FARM-RECORDS.md)。schema4旧服务也会拒绝schema5；不能通过降版本移除新资料或绕开校验。

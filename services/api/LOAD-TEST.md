# 本机有界业务负载

`tools/load-api.mjs` 只创建自己的全新临时目录、SQLite 文件和 `127.0.0.1` 随机端口服务。它不接受目标 URL、数据库路径、账户或服务配置；不会读取项目运行数据库，也不会访问已有服务、设备或公网。需要 Node 24.15.0 及以上，无需安装依赖。

在仓库根目录运行：

```powershell
node services/api/tools/load-api.mjs
node services/api/tools/load-api.mjs --duration 120 --workers 4
node services/api/tools/load-api.mjs --duration 300 --workers 16 --requests-per-worker 10000
node --test services/api/test/load-test.test.mjs
```

默认持续业务循环 60 秒、4 个 worker，每个 worker 最多 10000 个请求。`--duration` 允许 1–300 秒，`--workers` 允许 1–16，`--requests-per-worker` 允许 16–10000；总请求硬上限为二者乘积，最大 160000。未知、重复、缺值和越界参数直接拒绝。每个 HTTP 请求绝对超时为 5 秒、响应最多 256 KiB；全程另有“所选时长 + 30 秒”中断保护及有界关停等待。SIGINT/SIGTERM 会取消负载并尝试清理。

每个 worker 使用独立的新 development 账户，执行真实 HTTP 和 SQLite 事务：

1. 登录并确认初始资产为 80 积分、6 份饲料及契约中的样本库存，未登录读取必须返回 401。
2. 加入 2 个饲料包，同时发出相同幂等键的两次用券兑换：恰好一份原结果和一份重放；确认只扣 40 积分、增加 6 份饲料、使用一次优惠券，且只有一笔订单、一次库存扣减和一份收据。
3. 连续混合读取权威快照、重放原兑换、用不同幂等键竞争同一 revision 的购物车增加（恰好一份 200、一份 409），再用同一键并发移出商品（恰好一份原结果、一份重放），恢复空车并复核资产、订单、收据、库存和 revision。
4. 循环结束后关闭服务，以同一临时 SQLite 重启；重新登录所有账户，确认身份、空车、资产及兑换历史仍然一致。

每轮有 7 个请求，轮间最多等待 250ms。此固定节奏用于可重复的持续读写验证，没有自适应加压或最大吞吐量搜索。每个 worker 保留 2 个请求供重启后复核；预算不足以完成一整轮时提前停止，报告 `stoppedByRequestLimitWorkers`。此时 `passed: true` 证明预算内的业务不变量，不能把所选时长当成实际持续时长；应读取 `workloadElapsedMs`。

临时服务显式使用每 1000ms 最多 10000 个请求、每 1000ms 最多 1000 次开发登录的覆盖配置，数值写入 `rateLimit`。这些配置只存在于工具自己创建的服务，不修改默认限流或配置文件；生产默认限流由 API 规则测试独立验收。

业务时钟从固定白天测试时间开始，按真实单调elapsed推进，报告写明`businessClock`。这使服务重启、限流窗口和持续时间保持推进，同时避免运行主机跨上海午夜给固定工作集插入合法日同步版本冲突。真实日界、时钟回拨及跨日资格由独立API规则测试验收，负载报告不冒称这类时间边界验证。服务产品默认时钟没有被此工具修改。

标准输出仅一行 JSON 汇总：请求和响应数、预期 409/401 数、完成轮次、账户验证数、延迟分位、RSS 和 event loop 指标、固定分类的错误计数及清理结果。报告不包含账户名、用户标识、令牌、请求正文、URL、目录或数据库内容。任何意外状态、5xx、资产/回执不符、请求超时、中断或清理失败都令 `passed: false`，CLI 退出码为 1；通过为 0。非法参数在 stderr 返回固定提示，不回显参数。

清理前检查工具最初创建目录的绝对路径、临时根目录直属关系、固定前缀和随机后缀、目录类型及原始 realpath；不对用户输入构造的路径递归删除。成功和失败都会尝试关闭服务并清理本轮临时数据。清理被拒绝或失败会在报告中标记错误，退出非零。

`latencyMs` 包含完整响应读取和 JSON 解析，包含预期的 401/409；RSS 和 event loop 来自同一 Node 进程中的服务及负载客户端，包含初始化、采样与重启。短单测仅验证 1 秒业务循环和提前触达预算，不默认运行 120 秒负载；工具命名为 `load-api.mjs` 以避开 Node 默认测试发现规则，并用真实 `node --test` 子进程验证不会被当作测试入口执行。本机硬件、同步 SQLite、同进程客户端、轮间等待和单实例都会影响数值；没有制定生产 SLA，因此没有任意 p95 门槛，也不能据此声称生产容量、长期无泄漏、TLS/代理、多实例、真实平台 SDK、真机或农场设备已验收。
